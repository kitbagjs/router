# Upgrading to 0.33.0

## Breaking changes

### Title callback context

Title callbacks no longer receive `from` in their context. It previously contained the destination route, not the previous route. Remove references to `context.from`; use the callback's first argument when you need the destination route. `getParentTitle` remains available.

### Duplicate loader names

Adding a loader with a name already used on the same route now throws `LoaderNameConflict` instead of replacing the existing loader. TypeScript also rejects duplicate names across a route and its ancestors.

Give each loader a unique name, or remove the earlier registration if you only intended to keep the replacement. Two unnamed loaders both use `default` and therefore conflict.

See [Named loaders](/core-concepts/loaders#named-loaders).

## Deprecations

### Loader data in callbacks

Replace `route.data` in props callbacks with `route.getData()`, and replace `parent.data` in loader or props callbacks with `parent.getData()`. Pass a name for a named loader; omit it for the default loader.

| Before | After |
| --- | --- |
| `await route.data` (a lone default loader) | `await route.getData()` |
| `await route.data.project` | `await route.getData('project')` |
| `await parent.data` (a lone default loader) | `await parent.getData()` |
| `await parent.data.organization` | `await parent.getData('organization')` |

`parent.getData` can read loaders declared on any ancestor. Loader callbacks cannot read their own route's data; use `parent.getData` for dependencies on ancestor loaders.

See [Using loader data in props callbacks](/core-concepts/loaders#using-loader-data-in-props-callbacks).

### Parent props in callbacks

Replace `parent.props` with `parent.getProps()`. Pass a view name to read the props for a named view on the immediate parent.

| Before | After |
| --- | --- |
| `await parent.props` (a lone default props getter) | `await parent.getProps()` |
| `await parent.props.sidebar` | `await parent.getProps('sidebar')` |

The getters return promises, including when the loader or props getter is synchronous. The deprecated properties remain available in 0.33.0.

See [Parent Props](/core-concepts/component-props#parent-props).

### Component data reads

`router.route.data` remains available but deprecated in 0.33.0. Its deprecation began in [0.31.0](/upgrading/0.31.0#component-loader-data). Continue using [`useLoader`](/composables/useLoader) for reactive data, loading state, and errors in components.

[Full release notes](https://github.com/kitbagjs/router/releases/tag/v0.33.0).
